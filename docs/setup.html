Run CRKL-Space Locally

Start the database, backend, and frontend on your own computer with one command

CRKL-Space runs as three services: a MySQL 8.0 database with our sample data, a FastAPI backend, and a Next.js frontend. Docker Compose builds and starts all three, so you don't need to install MySQL, Python, or Node.js.

What you need

  • Docker Desktop (macOS, Windows, or Linux), running before you start.
  • Git, or download the code as a ZIP file from GitHub instead.
  • Port 3000 free on your computer. It's the only port CRKL-Space uses.
  • An internet connection the first time, to download the MySQL, Python, and Node.js images.

1. Get the code

Clone the repository and open its folder:

git clone https://github.com/CRKL-SDSU/CRKL.git
cd CRKL

Or, on GitHub, click Code → Download ZIP, unzip it, and open the folder in a terminal.

2. Configure

The .env file

The only file you need to create is .env, which holds the two database passwords. Copy the example in the CRKL folder:

cp .env.example .env

On Windows (Command Prompt), use copy .env.example .env. Then open .env in a text editor and replace both values:

SettingWhat it isExample
CRKL_DB_ROOT_PASSWORDPassword for MySQL's root account. Used only on the first start, to create the database and the application user.root-secret-123
CRKL_DB_USER_PASSWORDPassword for crkl, the account the backend uses. It can only read and write rows in crkl_db; it can't drop tables or change the schema.app-secret-456
  • Choose any values, but don't use single quotes (') in them.
  • Docker refuses to start if either value is missing, so you can't accidentally run with an empty password.
  • The passwords are applied only on the first start. To change them later, reset the database (see Stop and reset).
  • .env is ignored by Git, so your passwords are never committed.

Other configuration files

These are already set up for Docker. You don't need to edit them.

FileWhat it configures
docker-compose.yamlThe three services, the order they start in, and the one published port (3000). The backend and database are reachable only inside Docker.
backend/conf/docker.yamlHow the backend connects to MySQL: host mysql, port 3306, user crkl, database crkl_db. The password comes from CRKL_DB_USER_PASSWORD in .env.
specs/db/DDL.sql, specs/db/dummy_data.sql, docker/mysql/03-app-user.shRun by MySQL on the first start, in this order: create the tables, load the sample data, and create the crkl user.

3. Start

In the CRKL folder, run:

docker compose up --build

The first start takes a few minutes. Docker downloads the images, builds the backend and frontend, and MySQL creates the database and loads the sample data. Each service waits until the one before it is healthy:

  1. mysql starts and finishes loading the data.
  2. backend starts once it can log in to MySQL as crkl.
  3. frontend starts once the backend reports the database as connected.

Leave this terminal open; the logs of all three services appear in it. Later starts are much faster, because the images and data are kept.

4. Check that it works

  1. Open http://localhost:3000/explore.
  2. With Missions selected and Include related records checked, search for NASA.
  3. You should see 28 results. Uncheck Include related records and search again: 0 results, because no mission mentions NASA in its own fields.

See the Instructions for everything else you can do on the Explore page.

5. Stop and reset

To…Run
Stop the services (data is kept)Press Ctrl+C in the terminal, then docker compose down
Start againdocker compose up
Reset the database to the sample data (also applies new passwords from .env)docker compose down -v, then docker compose up

Troubleshooting

ProblemWhat to do
Cannot connect to the Docker daemonDocker Desktop isn't running. Start it, wait until it says it's running, and try again.
set CRKL_DB_ROOT_PASSWORD in .env (or …USER_PASSWORD…)The .env file is missing or a value is empty. Repeat step 2 in the CRKL folder.
port is already allocated for 3000Another program is using port 3000. Stop it, then run docker compose up again.
The backend never becomes healthy after you changed the passwordsThe database still has the old passwords from its first start. Run docker compose down -v, then docker compose up.
The page shows API returned 502 or 503The backend or database isn't ready yet, or has stopped. Check the terminal logs, wait a moment, and reload.

Running without Docker

For development, you can also run each service directly with Homebrew MySQL 8.0, Python 3.12, and Node.js 20. See “B. Local (without Docker)” in the README.
